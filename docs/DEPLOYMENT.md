# 静态部署

构建产物可部署到普通静态托管服务。公开站点不需要 Node 运行进程、数据库、GPU、模型 API 或环境变量。

## 生成与检查产物

在完整源码目录执行：

```sh
npm ci
npm run check
npm test
npm run build
npm run preview -- --port 5175
```

访问 http://127.0.0.1:5175，检查页面加载、视图切换、prefill/decode、输入编辑与撤销。预览完成后按 `Ctrl+C` 停止。

公开前还必须完成[发布检查清单](RELEASE.md)。发布的是同一候选提交生成的产物，不能在验收后手工修改 `dist/`。

## 托管设置

| 项目       | 设置                           |
| ---------- | ------------------------------ |
| 源码根目录 | 独立 `kvcache-lab` 仓库根目录  |
| 构建环境   | Node.js 22 或 24               |
| 安装命令   | `npm ci`                       |
| 构建命令   | `npm run build`                |
| 发布目录   | `dist`                         |
| 启动命令   | 无，使用托管平台的静态文件服务 |
| HTTPS      | 在托管平台启用                 |

支持上传目录的平台可以直接上传完整 `dist/`。自动从 Git 构建的平台应选择已通过检查的提交或版本标签。

构建会随附 `LICENSE` 和 `NOTICE.md`；缺少任一声明时会中止，不替换已有构建。部署目录应保留这两个文件、`index.html` 和完整 `src/`。分发构建产物同样需要随附版权和许可；不要仅上传脚本文件。

页面资源使用相对路径，可以放在域名根目录，也可以放在 `/kvcache-lab/` 这样的子目录。子目录入口需要以 `/` 结尾，或由服务器自动重定向到带 `/` 的目录地址。项目没有需要后端重写的客户端路由。

为 `.js`、`.css`、`.html` 提供正常的 JavaScript、CSS、HTML MIME 类型。由于文件名没有内容哈希，不要为页面和脚本配置长期 `immutable` 缓存；使用重新验证缓存，避免新页面混用旧脚本。

## 发布后核验

- 用站点的真实 HTTPS 地址打开页面，并在浏览器 Network 面板确认 HTML、CSS 和所有模块成功加载。
- 完成一次 prefill、逐 token decode、撤销，以及模型/设备/请求缓存视图切换。
- 在 390px 宽度检查 4 层 MHA、8 个 Q heads、16 token 的组合，确认页面无横向溢出，图内滚动和选中对象定位正常。
- 确认版权与来源说明随分发产物保留；核对站点版本对应已验收的提交。
- 对子目录部署，直接刷新子目录入口，确认资源路径没有回到域名根目录。

## 回退

保留上一个已验收版本的提交号或完整部署产物。出现问题时，在托管平台回退到该部署，或从旧版本重新构建后完整替换发布目录。不要混合新旧文件，也不要把旧文件追加到现有目录。

本地开发服务器仅用于本机开发和预览，不承担公开托管。报告安全问题见 [SECURITY.md](../SECURITY.md)。
